# Chart a decision map

Read [map format](map-format.md) for structure and tracker conventions.

1. Establish the destination from existing context. Ask only for consequential missing choices that determine the planning scope.
2. Identify precise questions, their dependencies, and areas not yet specifiable. If no substantial unknowns remain, deliver the settled route directly; create a map anyway only if the user requested that artifact.
3. Draft the map and the currently specifiable tickets. Give each ticket a question and evidence that could resolve it.
4. Save or publish within the requested destination and authorization. Create tickets before wiring references that need real identifiers.
5. If the request includes resolving the route, continue with [resolution](resolve.md). For charting-only work, deliver the map and stop. Research workers are optional; lack of a worker does not prevent inline investigation.
